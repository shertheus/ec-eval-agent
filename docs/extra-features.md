# 数据检查、实验对比与证据交付

这三项功能把实验执行前后的工作接到同一条流程中：先确认输入，再核对不同实验，最后交付结果文件。Pi、HTTP API 和命令行提供相同能力。

## 数据质量检查

```bash
./brain-eval inspect-data ds_xxx
```

系统核验观测文件 SHA-256，返回矩阵形状、节点标识、每列均值、标准差、最小值、最大值与非有限值计数。时间序列还返回一阶自相关。统计结果不包含原始观测，可直接用于确认导入内容与量纲。

样本充分性需要结合模型规模与研究设计判断；一阶自相关用于描述时间依赖。导入阶段已经检查 NaN/Inf 与常量通道，需要预处理的数据应先由用户处理，再创建新的数据快照。

Pi 示例：“检查这份数据的节点统计和时间相关性，再按 lag=1 生成 Granger 评测协议。”

## 跨实验对比

```bash
./brain-eval compare exp_first exp_second
```

默认要求两个或多个实验的数据内容、节点顺序、输入类型、真值标识和采样间隔一致，同时核对指标版本。相同数据的不同导入编号可以匹配。返回结果列出方法参数、设备、种子、指标汇总和失败运行，帮助识别真正改变的实验条件。

若需要并列查看不同数据，可显式使用：

```bash
./brain-eval compare exp_first exp_second --allow-different-data
```

结果按数据签名区分。每个汇总的重复单位是同一份数据上的模型种子。

Pi 示例：“对比这两个已完成实验，列出参数变化和各自的 F1、SHD、耗时、种子稳定性。”

## 证据 ZIP 导出

```bash
./brain-eval export exp_xxx
```

系统核验成功运行的 manifest，将协议、验证结果、图、指标、环境、日志与报告打包到 `workspace/exports/`，并返回 ZIP 的 SHA-256。包内 `bundle-manifest.json` 记录每个归档成员的哈希，便于交付后逐个验证。

归档包含各次尝试的证据与数据元信息；原始观测、原始真值和模型配置不进入归档。日志和元信息可能包含本机路径，公开分享前应检查这些字段。

Pi 示例：“收集实验结果并导出证据 ZIP，给出实验编号、文件位置和 SHA-256。”

## 功能验收

`tests/test_analysis_tools.py` 通过实际 Granger 运行检验统计值、匹配与不匹配数据的对比、ZIP 内容及其哈希，并验证修改观测或指标后系统会拒绝继续使用。真实模型系统评测另外记录 Pi 对数据检查、收集和导出工具的调用结果。
