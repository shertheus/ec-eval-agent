# 系统评测报告：固定脚本与 Pi Agent

评测日期：2026-11-15。系统在 10 个固定任务上分别运行无 AI 脚本与真实 Pi Agent，共 20 次独立执行。Pi 完成 **10/10** 个任务，固定脚本完成 **10/10** 个任务；协议正确项分别为 **10/10** 与 **10/10**，证据完整项分别为 **10/10** 与 **10/10**。这组评测检验自然语言需求能否沿着“数据—协议—执行—证据”完成交付。

## 任务与执行条件

任务覆盖五种方法、跨方法与种子的组合、无真值导入，以及输入不兼容、非有限值和超时三类异常。每个任务先固定数据、参数、种子和超时，再执行两个入口；入口顺序使用种子 `20261115` 打乱，每次使用独立后端、数据目录和 Pi 状态。

- 运行平台：Linux x86_64；Python 3.11.10、PyTorch 2.7.1+cu128、gCastle 1.0.3；算法全部使用 CPU，线程数 2。完整版本见 [环境记录](../examples/reports/system-eval/environment.json)。
- Agent：Pi 1.5.0，服务模型标识 `deepseek-latest-flash`，OpenAI Chat Completions 兼容接口，真实联网调用。该标识由服务端提供。
- 基线：预先编写的确定性 Python 脚本，直接调用相同 API，执行数据检查、协议验证、提交、等待、收集和导出。
- 配对数据：9/9 组有效数据的观测 SHA-256 一致。含 NaN 的任务应在创建数据集之前被拒绝。
- 单个 Agent 任务上限 180 秒；每个任务、每个入口执行一次，首次结果全部保留。计时从后端就绪后开始，包含脚本运行或 Pi 启动、模型推理、工具调用与结果交付。

预先固定的 [任务与源码哈希](../examples/reports/system-eval/spec.json) 的 SHA-256 为 `0df9ca0c9f96fb3d72ccbc46e18d8ac765b2ab9228702575b555902b903b0cad`。完整的提示生成逻辑和判断器见 [run_system.py](../benchmarks/run_system.py)。导入样例由固定随机数生成，不包含受试者数据。

**任务完成**要求实际状态、协议与证据同时满足任务定义。成功任务必须执行全部运行并导出结果；异常任务必须产生指定的拒绝或失败状态。**协议正确**核对数据生成配置、标准化算法参数、CPU 设备、种子、超时与尝试次数。**证据完整**核对工具实际调用、报告和 ZIP 文件，并再次通过后端校验成功运行的文件 manifest；拒绝任务以真实工具拒绝记录为证据。

因此，T08–T10 的“通过”表示系统按预期处理异常。T10 的算法运行状态是失败，仍保留在逐任务记录中。各项指标由后端状态、文件与工具事件判定。

## 失败案例与系统处理

| 任务 | 失败原因 | 预期处理 | 实际证据 |
|---|---|---|---|
| T08 | IID SEM 没有时间顺序，无法按 Granger 的滞后语义使用 | 验证阶段拒绝，不提交实验 | 验证返回 valid=false，实验列表为空；是否满足见逐项结果 |
| T09 | CSV 含 NaN，无法直接进入数值拟合 | 导入阶段报错，保留原输入 | prepare_dataset 返回导入错误，未创建数据集 |
| T10 | GOLEM 设定 1,000,000 次迭代，超过 5 秒预算 | 停止运行，保存失败原因与证据 | 任务记录 failed/timeout，失败报告和 ZIP 可供检查 |

这些场景将数据修正、方法选择和计算预算明确留在协议层。用户收到错误原因后，可以准备新数据或建立新协议，历史运行与失败证据继续保留。

## 补充验收：模型参数错误的恢复

在 0.2.0 Docker 容器的新增功能任务中，Pi 将算法种子误放进 Granger 的 `params` 字段，两份协议均被验证器以 `unsupported granger parameters: ['seed']` 拒绝。Pi 根据返回信息将种子移到协议级 `seeds`，验证通过后提交；两个实验均成功，随后完成同数据对比和 ZIP 导出。

这次调用展示了协议校验的作用：模型组织参数，后端检查字段，纠正后的协议才进入执行队列。该任务单独记录于 [容器验收证据](../examples/reports/system-eval/docker-020-acceptance.json)，不并入上述 10 任务统计。

## 对使用方式的启示

固定脚本适合已经明确的批量协议，Pi 将同一套能力放进自然语言交互中。二者共享持久化后端，使研究者可以在对话中组织实验，也可以按固定参数重复执行。端到端耗时将模型推理与工具往返计入，便于选择交互任务的预算。

本次任务由结构化配置生成自然语言提示，统计单位为每个入口的 10 次执行；结果描述这组固定任务。脚本编写时间未计入，因此耗时表用于比较执行开销。算法使用安装级训练预算，图恢复指标应在专门的方法比较实验中分析。

## 复现

在项目 Python 与 Node 环境就绪后运行：

```bash
python benchmarks/run_system.py \
  --output logs/system-eval-new \
  --env-file /absolute/path/to/deepseek.env \
  --model YOUR_MODEL --proxy http://127.0.0.1:18083
python benchmarks/summarize.py logs/system-eval-new .
```

`--output` 必须为新目录。模型与接口在用户的配置文件中提供；无需代理时传 `--proxy ''`。运行器创建并关闭自己的后端，不占用正式实验队列。汇总脚本生成上述公开结果与本报告，模型与环境版本从运行记录自动写入报告。
