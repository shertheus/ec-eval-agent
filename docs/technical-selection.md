# 技术选型：自然语言入口与可复现实验后端

本系统服务于脑连接方法的日常评测：研究者提出数据、方法与预算要求，系统将其转为明确协议，执行算法并交付可核验的结果。选型重点是交互是否直接、实验是否持久保存、方法接口是否统一，以及安装后能否沿用同一条工作流。

## Agent 框架比较

| 决策维度 | 固定 Python 脚本 | Pi + 领域工具（采用） | LangGraph |
|---|---|---|---|
| 用户入口 | JSON 配置或命令行参数 | 终端自然语言对话，内置交互界面 | 用状态图组织流程，交互入口由应用提供 |
| 实验步骤表达 | 程序显式编排 | 模型选择工具；后端校验协议 | 节点、边与状态显式建模 |
| 接入算法服务 | 直接调用 HTTP API | TypeScript 扩展注册有类型的工具 | 将 API 调用封装为节点或工具 |
| 持久化 | 由项目后端负责 | 会话由 Pi 管理，实验由项目后端管理 | 提供状态持久化、durable execution 与 interrupt 能力 |
| 安装组成 | Python 与算法依赖 | Python、Node.js、Pi 和算法依赖，打入一个镜像 | Python 与 LangGraph，可按需配置持久化和应用界面 |
| 适合本项目的部分 | 预设批量任务、回归测试、系统评测基线 | 临时组合数据、方法与参数，交互查询结果 | 分支较多、需要人工审批或恢复复杂 Agent 状态的流程 |
| 本项目落地状态 | 已实现并作为无 AI 基线实测 | 已实现 11 个工具并接入真实模型 | 根据官方文档进行能力比较 |

选择 Pi 的直接原因是项目以终端交互为入口，Pi 已提供对话、JSON 模式、模型配置和扩展接口。领域扩展将实验能力映射为 11 个工具，研究者可以在一个会话中完成数据检查、协议提交、结果查询和导出。容器同时封装 Node 与 Python，用户安装时只需处理 Docker 和模型配置。

LangGraph 的显式状态图适合多阶段分支、人工审批与复杂恢复流程。本项目将长期运行的训练任务交给独立后端，Agent 侧主要组织工具调用，因此当前采用 Pi；若后续加入自动搜索、人工审核节点或跨会话研究流程，可保留后端 API，将交互层换成 LangGraph。LangGraph 的状态检查点保存工作流状态；训练能否从某个 epoch 继续取决于算法自身是否实现检查点。

固定脚本保留为正式入口。参数已经明确的重复实验可以直接运行脚本，临时需求则由 Pi 组织。两者调用同一套 API，使用相同的校验、调度和指标实现。二者的实际完成率与耗时见 [系统评测报告](system-evaluation.md)。

## 算法库与方法接口

| 方案 | 集成收益 | 需要承担的工作 | 决策 |
|---|---|---|---|
| gCastle | 同一包提供 SEM 数据、NOTEARS、GOLEM、DAG-GNN；可统一版本与调用入口 | 记录不同方法的参数、设备与输出方向；处理 NetworkX 兼容 | 作为静态因果发现与 SEM 数据的主要依赖 |
| 分别集成各论文仓库 | 可接入作者最新实现和特殊训练流程 | 多套环境、数据格式和结果约定需要逐一适配 | 特殊方法按需引入；Neural-GC 固定源提交并保留许可证 |
| 全部自行实现 | 完全控制接口 | 需重新验证数值方法与训练实现 | 将原创开发集中于协议、调度、评价和证据管理 |

gCastle 中的静态方法将每一行作为观测，Granger 与 Neural-GC 使用明确的时间滞后。后端按输入语义检查方法适用性，统一“源节点在行、目标节点在列”的矩阵方向。它们可以在同一平台服务于脑连接研究，同时保留各自的建模假设。

## 执行与存储

采用 FastAPI + Pydantic 建立严格输入契约，SQLite WAL 保存任务与事件，文件目录保存数组、日志与报告。算法在独立进程中运行，调度器负责超时、取消和重试。自然语言会话结束后，已提交任务继续由后端执行。

对于单机课程项目，这一方案可直接随应用启动；Redis + Celery 需要增加服务与队列配置，其优势在多工作节点和并发负载下更明显。当前串行调度让资源占用与失败定位更清楚。未来增加多工作节点时，应扩展任务领取和资源分配机制，而保持协议和结果格式稳定。

## 安装方案

| 方案 | 使用场景 | 迁移内容 | 本项目用途 |
|---|---|---|---|
| 复用 Conda | 已有兼容算法环境的开发服务器 | 项目源码与运行入口 | 开发与原生测试，避免更改共享环境 |
| requirements + npm lock | 用户自行管理环境 | Python 依赖、Node、npm 锁定依赖和源码 | 源码安装和维护 |
| Docker | 录屏演示、安装交付与环境复现 | 镜像、安装脚本、模型配置模板 | 默认交付方式 |

Docker 镜像包含 CUDA 版 PyTorch，CPU 模式可直接启动。GPU 模式还需要宿主机驱动与 NVIDIA Container Toolkit。镜像将配置、输入、结果和 Pi 状态分开挂载，更新软件时可以保留实验记录。模型密钥由用户在镜像外配置。
